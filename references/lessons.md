# 实战经验（一次出 7 版宣传片总结，2026-10）

## 审美与反馈
- 用户最认可的是**有强叙事 + 炫酷特效**的赛博 HUD 版，其次是 2.5D 微缩城市的创意（但制作要精）。风格多不如一版做精。
- 最大的扣分项是**声音**：合成的高音“叮”刺耳、合成 BGM 不高级 → 用成品配乐 + 调性匹配的柔和动效音（见 `bgm-workflow.md`）。
- 节奏宁可稍慢：卡点后整体偏快会被嫌“赶”，各段速度控制在 0.85–1.25 倍。

## 叙事模板（产品/平台宣传片，60–90 秒）
钩子（世界观 + 问题）→ 痛点（混乱可视化）→ 一次真实调用的全过程（最有说服力）→ 能力全景（产品矩阵）→ 3–4 个技术亮点（每个 3–4 秒一句话 + 一个微动画）→ 数据（标统计时点）→ 面向谁/怎么用（行动号召）→ 口号 + 片名。

## 画面
- 字幕、标签全部画在 canvas 里，**先抽 6–9 帧拼联系表检查**重叠、出界、被遮挡，再整片渲染；改完只抽问题帧复查。
- 横向滚动的长条/时间轴：当前项字号随字数自适应，间距要大于最长词宽，否则会和下一项叠在一起。
- 等轴城市：主角（如小车）别被前景楼挡住——把路前一排楼压低；镜头关键帧加 `cy` 控制垂直构图；夜景光晕要克制（只给少量窗口/楼顶加 glow）。
- 卡片/面板的中英文标签分行放，别同一行左右挤。
- 片名、终场文字放在关键视觉元素上方，避免和光环/HUD 圈重叠。
- 用 `tOut → 片时间` 映射时，GLITCH、字幕、cue 都按片时间写，统一换算，不要两套时间混用。

## 性能（1080p，本机 24 核 + 独显）
- 2D canvas 场景 `--nogpu --mb 3~4`：约 0.3–0.5 秒/帧，90 秒片约 20–30 分钟。
- WebGL 水墨等重着色器 `--hwgpu --mb 2`：约 3 秒/帧，60 秒片约 1.5 小时，提前告诉用户。
- 多条片可以并行渲染（后台任务），但会互相拖慢。

## 声音
- 每个 cue 都要有声音，但按“重要程度”分三档：关键（重音/片名）> 结构（换场/关卡）> 点缀（打字/滴答）。
- 合成乐器的音阶递进（do→re→mi）保留，但必须在配乐的调里、柔和音色、降八度。
- 音效电平别被峰值保护“整体压低”；只改声音时直接重混 + 替换音轨，几分钟搞定。
- 带音乐的成片峰值常因 AAC 编码冒出 0 dBFS，混音末端加 limiter。

## 口径（企业对外视频）
- 数字只用已有统计并写明统计时点；示意数据要在交付说明里标注“示意”。
- 第三方模型名只写确认接入的；不写内部域名、账号、人名。
- Remotion 对 >3 人营利公司要买授权；sy-styles-20（MIT）与 HyperFrames（Apache-2.0）无此限制。
