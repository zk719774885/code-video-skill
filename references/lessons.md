# 实战经验

分两部分：**一、判例式准则**（审美和流程，每条 = 规则 + 判例 + 自检问句）；**二、技术坑与技巧**（性能、工具、实现细节）。

## 一、判例式准则

**用法**：交付前逐条过一遍，在项目的 `REVIEW.md` 里写 `编号 ✓` 或 `编号 ✗（镜头 / 时间码）`。可以有意违反某条（风格需要时），但要写明违反了哪条、为什么。
**编号规则**：V 画面、R 节奏、S 声音、C 文案与口径、P 流程。**编号一经发布不重排，新条目只追加**，废弃的条目标「（废止）」保留编号。判例里的引号是可哥原话；没有原话的写「反馈」。
格式借鉴 video-shotcraft（Apache-2.0）的判例式审美准则，内容全部来自我们自己的项目。

### 画面（V）

**V1. 画面要丰富，不能「素」**
规则：每个镜头要有层次：前中后景或多层纸张的视差、主角的光、常驻的慢速粒子（尘、雪、雨、花瓣）、至少一种运镜；水墨这类留白画风也要加淡彩色晕和粒子。
判例：可哥看《此心光明》第一版（纯黑白留白的中国水墨）后说：「画面表现上太素了」，要更多复杂的运镜、动效、动画和层次。
自检：随便暂停一帧：画面里有几层？主角被照亮了吗？有没有东西在慢慢动？

**V2. 每镜一个主角，主角够大，不能空场**
规则：按 `composition.md`：主角 ≥ 1/4 帧高；最大物体 < 10% 帧高持续超过 1.5 秒是空场。
判例：《此心光明02》人物只占画面高度约十分之一，多帧只有一个小字漂在大片纸上，复盘时判为「廉价」的主要原因。
自检：`frame_metrics.py` 报空场了吗？每个镜头的主角是谁、占多高？

**V3. 字幕读得清：横屏 ≥ 5% 帧高，竖屏缩到 480 宽仍可读**
规则：按 `composition.md` §3，量成片实际像素。
判例：《此心光明02》竖屏字幕约 50px（2.6% 帧高），手机上读着吃力。
自检：每个有字幕的镜头抽一帧缩到 480px 宽，还读得清吗？

**V4. 画面用代码生成，不用视频模型、不拿 AI 生图当主画面**
规则：画面由代码生成（Canvas、着色器、Three.js、Blender 程序化）；追求真实感走实物材质和 3D（`viral-study.md` 路线 B、C）。公有领域的真实史料图（Commons）可以当贴图、档案卡片。
判例：此心光明第三季开工时可哥纠正：「我需要的是代码生成视频的技术栈，不是让你用视频模型去生成视频」。
自检：片子里有没有哪一帧的主画面来自视频模型或 AI 生图？

**V5. 每支片开头是封面，并单独交一张封面图**
规则：第 0 帧就是完整封面（片名大字 + 主视觉），约 1 秒后 0.4 秒叠化进正片（`tools/addcover.py`），另存 `poster.jpg` / 封面 jpg。
判例：可哥：「每个视频开头要是封面，并且单独给一张封面图」——抖音默认取第一帧当封面。
自检：暂停在第 0 帧，它能直接当封面用吗？

**V6. 风格多不如一版做精；强叙事 + 炫酷特效最受认可**
规则：同一题材不要铺很多浅尝辄止的风格版本；选一两种做到位。做系列时可以同一文案出两种风格给可哥对比。
判例：一次出 7 版宣传片，可哥最认可有强叙事加炫酷特效的赛博 HUD 版，其次是 2.5D 微缩城市（但要求制作更精）。
自检：这一版有没有一个能让人记住的招牌镜头？

**V7. 文字和关键元素不重叠、不出界、不被挡**
规则：先抽 6–9 帧拼联系表检查重叠、出界、遮挡，再整片渲染；片名和终场文字放在关键视觉上方，别压在光环和 HUD 圈上；中英文标签分行放；横向滚动的列表间距大于最长词宽。
判例：宣传片多版出现标签互相叠、等轴城市里小车被前景楼挡住、片名压在光环上。
自检：联系表上有没有任何字被挡、被裁、互相叠？

**V8. 符号类图形由数据生成并脚本校验，不手画**
规则：卦画、星图、乐谱、化学式、地图坐标这类「有对错」的图形，一律从数据生成（卦 = 6 位二进制），并写脚本校验（卦名和爻画对得上、方位对得上），每期附 `FACTS.md`。
判例：对标的易经号卦画被弹幕挑错（反馈，见 guoxue 对标拆解）。
自检：片子里每个卦、每个符号，有数据来源和校验结果吗？

### 节奏（R）

**R1. 宁慢勿赶**
规则：卡点后各段速度控制在 0.85–1.25 倍；关键信息落定后停 1–1.5 秒再切（`composition.md` §4）。
判例：卡点后整体偏快，被可哥嫌「赶」。
自检：第一次看的人，每个镜头都看清了吗？

**R2. 入场即停、落位即切都是缺陷**
规则：元素入场后完全静止不超过 3 秒；每段最后一个元素落位后稳定 1–1.5 秒再离场。
判例：来自 anything2explainer 的两类缺陷判据，用于《此心光明》第三季之后的片子。
自检：有没有超过 3 秒什么都不动的镜头？有没有刚落位就切走的？

### 声音（S）

**S1. 用成品配乐，合成音要柔**
规则：配乐用成品曲；有音高的动效音进配乐的调、柔和拨弦音色、降八度（`mixbgm.py` 已实现）。
判例：宣传片最大的扣分项是声音：合成的高音「叮」刺耳、合成 BGM 不高级（反馈）。
自检：闭眼听：有没有刺耳的高音？配乐听起来像成品吗？

**S2. 配乐整首连续，不剪拼**
规则：只选起点偏移让最重要的重拍落在片名上，结尾约 4 秒长淡出；画面去贴音乐，不剪音乐（`bgm-workflow.md` §4）。
判例：QWERTY 按小节剪接配乐，可哥觉得听起来「突然变成另一段、被截断」，更想要整首连续、流畅的 BGM，卡点不用刻意。
自检：整片听一遍，音乐有没有任何一处听着像被剪过？

**S3. 重击对齐真实起音，不能「双响」**
规则：impact、boom、stamp 对齐 `beats.py` 的 `onsets` / `accents`；`mixbgm.py` 报「双响风险」必须处理。
判例：QWERTY 片名的重击按拍格的小节首拍放，比真实 Drop 晚 0.25 秒，可哥听出来像「音乐被剪了一刀」。
自检：mixbgm 输出里有没有「双响风险」？

**S4. 每个可见动作都有声音，按重要程度分三档**
规则：关键（重音、片名）> 结构（换场、关卡）> 点缀（打字、滴答）；音效总线比音乐低 5–9 dB，不要因为个别峰值把整条音效压低。
判例：音效被峰值保护整体压低了 8 dB，画面显得单调（反馈）。
自检：静音看一遍：哪些动作本该有声音？

**S5. 响度用静态增益**
规则：测一次整体响度 → 整条乘同一个增益 → 限幅；不用单遍 loudnorm。成片 -14 ~ -16 LUFS，真峰值 ≤ -1 dBTP。
判例：单遍 loudnorm 把安静段抬、重拍压，QWERTY 的音乐忽大忽小（反馈）。
自检：ebur128 的响度和 LRA 是多少？

### 文案与口径（C）

**C1. 每支成片附发布文案**
规则：成片同目录写 `发布文案.md`：作品标题（≤ 30 字）、作品简介（正文 + 话题标签），可加封面字、置顶评论；交付时按发布顺序汇总。国学题材避免「算命、改运、吉凶」这类词。
判例：可哥：视频多、风格多、版本多时，不知道发哪条、怎么写，要能直接复制粘贴发布。
自检：`发布文案.md` 在不在？标题 ≤ 30 字吗？

**C2. 企业片的数字和名称口径**
规则：数字只用已有统计并写明统计时点，示意数据在交付说明里标「示意」；第三方模型名只写确认接入的；不写内部域名、账号、人名。
判例：企业宣传片交付要求（反馈）。
自检：片中每个数字都有出处和时点吗？

### 流程（P）

**P1. 首检不交给可哥，交付前过独立评委**
规则：交付前自己抽帧、跑 `frame_metrics.py`、按 `review.md` 开干净上下文的评委打分，改一轮再评。
判例：《此心光明》前两季都是自己做自己查，复盘发现构图问题一直没被发现（确认偏差）。
自检：REVIEW.md 里有两轮评委分数吗？

**P2. 先做开头 10 秒试片，确认后逐段推进**
规则：见 SKILL.md 四步法第 4 步。
判例：来自小冯不意why 的教程，可哥采纳为默认流程。
自检：这一版是不是一口气做完没给可哥看过开头？


## 二、技术坑与技巧

### 性能（1080p，本机 24 核 + 独显）
- 2D canvas 场景 `--nogpu --mb 3~4`：约 0.3–0.5 秒/帧，90 秒片约 20–30 分钟。
- WebGL 水墨等重着色器 `--hwgpu --mb 2`：约 3 秒/帧，60 秒片约 1.5 小时，提前告诉用户。
- Three.js + Bokeh 景深 + Bloom + 2048 阴影 + 2D 合成 `--mb 3`：约 3 秒/帧，132 秒片约 3.3 小时（BokehPass 是大头）。
- 整片用 `build.js full --jobs N` 分段并行：同一个片子开 N 个浏览器各渲一段。N 约取 CPU 线程数的 40%（本机 24 线程用 10：90 秒片 `--mb 2` 只要 3.6 分钟）。多条不同的片同时渲也行，但会互相拖慢。
- 超过 10 秒的片，build.js 会先在中段试渲 0.5 秒，打印每帧耗时和预计总时长；每帧超过 3 秒会提示查性能坑。
- **2D Canvas 性能坑（严重）**：对大量笔画逐个设 `ctx.filter = 'blur(...)'`（想做背景景深），无头 Chromium 下每帧从 0.5 秒涨到 20 秒以上，90 秒片要 3 小时。要虚化就先画到一张离屏小画布，再整体模糊一次；或者直接降透明度、加粗线宽冒充虚焦。`shadowBlur` 发光也贵，但量不大时可以接受。
- 重 2D 场景（大量路径、发光）`render.args` 写 `--hwgpu` 也能再快约 3 倍，不只是 WebGL 才用。
- `--mb` 子帧的 t 在第 0 帧会略小于 0：render.js 已夹到 ≥ 0，但场景里按帧号取数组（颗粒贴图、帧序列）仍要做正模 `((i % N) + N) % N`，否则拿到 undefined，createPattern 报错会直接中断渲染。

### 工具坑（Windows）
- winget 装的 ffmpeg 8 没有 fontconfig 配置，`drawtext` 不写 `fontfile` 会**段错误崩溃**（不是普通报错）。一律写 `drawtext=fontfile='C\:/Windows/Fonts/arial.ttf':…`，盘符冒号要转义。看视频用 `tools/contact.py`（已处理好，带时间码）。
- PPT 里内嵌的视频、GIF：pptx 就是 zip，直接从 `ppt/media/` 解出来看。
- Node 24 的 `fs.cpSync` 复制到含中文的目录时**什么都不复制也不报错**；要复制目录就逐个文件 `readFileSync` + `writeFileSync`（newproj.js 已改）。
- PowerShell 的 `Set-Content -Encoding utf8` 会写 **BOM**，Node 的 `JSON.parse` 直接报错。build.js、addcover.py 读 JSON 已去 BOM；自己写 JSON 尽量用 Write 工具或 Python。
- `cv2.imread` 不认中文路径（返回 None 不报错）：用 `cv2.imdecode(np.fromfile(路径, np.uint8), cv2.IMREAD_COLOR)` 读，`cv2.imencode('.png', img)[1].tofile(路径)` 写。
- ffmpeg 8 的 `h264_nvenc` 要 NVIDIA 驱动 ≥ 610，驱动旧会直接失败；编码前先试一下，不行就回退 `libx264 -crf 17`（addcover.py 已这样做）。
- **成片不要二次压缩**：要改片头片尾、加封面，都从原始逐帧图重新编码一次，别拿压好的 mp4 再压（实测码率 11.7 → 8.9 Mbps）。

### 2D Canvas 技巧（通用）
- **自制小型透视 3D 线稿**（不想上 Three.js 时）：顶点乘相机矩阵再透视除法得到屏幕坐标；面按平均深度从远到近排序再画（画家算法）；线宽和透明度随深度衰减，远处细而淡，立体感立刻出来。
- **笔触辉光**：同一条路径画三遍。底层粗线、低透明度加 `shadowBlur` 当光晕；中层正常线；最上面一条细的白色高光芯。笔尖处再撒几颗随时间衰减的火花粒子，「正在书写」的感觉很强。
- **弹簧过冲会让半径变负**：`spring()` 会冲过 1 再回来，用它驱动缩放时 `arc` 的半径可能小于 0，`ctx.arc` 直接抛异常并中断渲染。凡是由动画算出来的半径都包一层 `Math.max(0, r)`。
- **抠图**：OpenCV `grabCut` 用掩码初始化（先给确定前景、确定背景、可能前景三类）比矩形初始化干净很多；抠完边缘羽化 1–2 像素。

### 加封面
抖音取第一帧当封面。不重渲正片的做法：单独做一个 2–3 秒的封面场景（第 0 帧就是完整封面），用 `tools/addcover.py` 接到片头，0.4 秒溶接；配乐起点前移、音效整体后移、重混；封面第 0 帧作为 `attached_pic` 写进 mp4。

### 读客户提供的素材
- 企业给的「提资」里常混着**第三方厂商的演示视频**（片头是厂商 Logo）和带 **DEMO 水印**的录屏。看总览图时专门检查片头、片尾和水印，在摘要里标「不建议用」，并问用户要无水印的原片。
- 大文件（模型、CAD、压缩包、上 GB 的 Excel）只记下存在，不打开；长文档用脚本提取文字，边读边把要点写进摘要文件，后面只看摘要（省额度）。

### 叙事模板（产品/平台宣传片，60–90 秒）
钩子（世界观 + 问题）→ 痛点（混乱可视化）→ 一次真实调用的全过程（最有说服力）→ 能力全景（产品矩阵）→ 3–4 个技术亮点（每个 3–4 秒一句话 + 一个微动画）→ 数据（标统计时点）→ 面向谁/怎么用（行动号召）→ 口号 + 片名。
